# 競馬AI予測システム

netkeibaからデータを自動収集し、機械学習で各馬の勝率を推定して、期待値の高い馬券を提案するシステムです。

---

## できること

| 機能 | 説明 |
|------|------|
| **データ収集** | netkeiba.comからレース結果・馬の過去成績・血統・オッズを自動取得 |
| **学習** | LightGBM LambdaRankで「レース内の着順」を予測するモデルを訓練 |
| **予測** | 未来のレース(出馬表が公開済み)に対して各馬の勝率と期待値を算出 |
| **シミュレーション** | 過去データで「このモデルで賭けていたら回収率は何%だったか」を検証 |

---

## セットアップ (初回のみ)

### 1. Python環境の準備

Python 3.11以上が必要です(3.13・3.14で動作確認済み)。

```
cd netkeiba_CNN
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

pip を先に更新するのは、pip 自身が内蔵する証明書ストア(certifi)を新しくするためです。
既存の `.venv` を使い回す場合も `pip install -r requirements.txt` を再実行すれば、certifi が下限の版以上に更新されます。

### 2. 動作確認

```
python -m pytest tests/
```

全テストがパスすればOKです。

## 使い方: ステップバイステップ

**全体の流れ:**

```
スクレイピング → 特徴量生成 → 学習 → 予測
    (1)            (2)        (3)    (4)
```

各ステップは必ずこの順番で実行してください。

---

### ステップ1: データ収集 (スクレイピング)

netkeibaからレース結果・馬の過去成績・血統データを取得します。

#### 基本コマンド

```
python main.py scrape --start 開始日 --to 終了日
```

日付は `YYYY-MM-DD`(日指定) または `YYYY-MM`(月指定) のどちらでもOKです。

#### 実行例

```bash
# 2024年1月だけ取得
python main.py scrape --start 2024-01 --to 2024-01

# 2024年の1年分を取得
python main.py scrape --start 2024-01 --to 2024-12

# 2020年から2025年まで5年分を一括取得
python main.py scrape --start 2020-01 --to 2025-12
```

#### 全データを取得して本格的に学習したい場合

netkeibaに過去データがある範囲(おおむね2008年以降)を取得できます。
推奨は **5年分以上** です。多いほどモデルの精度が上がります。

```bash
# 推奨: 2018年〜現在(約7年分)
python main.py scrape --start 2018-01 --to 2025-12
```

**所要時間の目安:**
- 1年分 ≒ 約3,500レース × 各レース平均15頭 = 約52,500ページ
- netkeibaへの負荷を避けるため1秒間隔でアクセスするので、1年分 ≒ **約15時間**
- 5年分 ≒ 約3〜4日 (PCをつけっぱなしにしておく必要があります)
- 一度取得したページはローカルに保存されるので、**2回目以降は未取得分だけ**が追加取得されます

**途中で止まっても大丈夫:**
- 取得済みデータはすべて `data/html/` にgzip保存されており、再実行時にスキップされます
- ネットワークエラーで個別レースの取得に失敗しても、バッチ全体は止まりません
- 中断後に同じコマンドを再実行すれば、続きから取得します
- 取得に失敗したページは `data/scrape_failures.tsv` に記録されます(`audit` コマンドで未解消のものを確認できます)

**馬の成績ページの更新:** 保存済みの成績ページに処理中のレースが載っていない場合(ページがレースより前に保存された場合)は、
自動で再取得します。追加取得(毎週・毎月の scrape)で、前回以降に走ったレースが過去走から欠けるのを防ぐためです。
以前の版で追加取得をしていた場合は、その期間を再度 `scrape` すると古いページが取り直されます。

#### テスト用 (少量で動作確認)

```bash
# 最初の10レースだけ取得して動作確認
python main.py scrape --start 2024-01 --to 2024-01 --limit-races 10
```

#### データの検査

```
python main.py audit
```

DBの整合性と欠けを検査し、検査ごとの件数と例を表示します(対象はJRA平地の確定レース)。問題の一覧は `data/audit_report.csv` に保存されます。

| 検査 | 内容 |
|------|------|
| race_missing_fields | 日付・距離・コース種別・開催場の欠損 |
| n_horses_mismatch | 結果表の行数が成績ページの頭数と一致しない |
| no_winner / missing_tansho_return | 1着馬・単勝払戻が無い |
| tansho_payoff_mismatch | 1着馬の単勝払戻が 単勝オッズ×100 と一致しない(パース誤り、または同着) |
| missing_odds | 完走馬の単勝オッズが欠損 |
| rank_time_inversion | 着順が下の馬の方がタイムが速い(降着は除く) |
| horse_page_missing / horse_page_stale | 出走馬の成績ページが無い / ページにそのレースが載っていない(古い) |
| ped_missing | 血統が無い |
| scrape_failure_unresolved | 取得に失敗し、まだ取り直されていないページ |

`build-features` の前に実行し、NG の件数が出走数に対して無視できない割合なら、原因を直してから学習してください。

### ステップ2: 特徴量生成

収集したデータから、モデルが学習に使う数値データ(特徴量)を計算します。

```
python main.py build-features
```

SQLiteのデータを読み込み、以下のような特徴量をParquetファイルとして出力します:
- 各馬の直近3走/5走/全走の平均着順・頭数で割った相対着順・賞金・着差・上がり3F (JRA平地の過去走のみで集計)
- スピード指数(場・コース種別・距離ごとの基準タイムとの差を、当日の馬場差とクラスで補正したもの)の直近3走/5走平均・5走最大
- 距離帯・コース種別・競馬場ごとの相対着順
- 過去5走のクラス水準と、前走からの昇級・降級
- 脚質(過去5走の1角での相対位置から 逃げ/先行/差し/追込/不明 に分類)
- 騎手・調教師の複勝率(直近1年。出走数が少ない場合は平均値に寄せて推定)
- 種牡馬の産駒複勝率(同コース種別・同距離帯)、父・母父のID
- 馬体重・斤量・枠番・出走頭数・レース間隔 など

障害レース・地方競馬・出走取消/除外の馬は対象外として除外されます。

- 過去走の人気の平均(直近5走)と、過去走の (人気 − 着順) の平均(正なら市場の評価より上位に来ている)

**パーサー更新後の注意:** 頭数・クラス、および過去走の天気・馬場・騎手・斤量・オッズ・人気・馬体重・ペースの列は
HTMLの再パースで埋まります。既存の `data/` がある場合は、
`build-features` の前に一度 `python main.py reparse` を実行してください(保存済みHTMLから再生成するため通信は発生しません)。

### ステップ3: 学習

#### configの設定 (学習前に確認)

[config/config.yaml](config/config.yaml) を開いて、スクレイピングした期間に合わせて設定を変更してください:

```yaml
model:
  # 学習に使う年(リスト)
  target_years_train: [2018, 2019, 2020, 2021, 2022, 2023]
  # 検証用の年(early stoppingとキャリブレーションに使用)
  target_year_val: 2024
  # テスト用の年(最終評価用)
  target_year_test: 2025
```

**ルール:** train < val < test の時系列順にしてください。
未来のデータで学習してしまうと、見かけ上の精度は高くなりますが実際には使い物になりません。

#### 学習の実行

```bash
# 通常の学習
python main.py train

# ハイパーパラメータの自動探索付き (時間がかかるが精度が上がる可能性あり)
python main.py train --tune
```

学習が完了すると `models/` フォルダに以下が保存されます:
- `lgb_lambdarank.model` — メインの予測モデル
- `lgb_binary.model` — 比較用の二値分類モデル
- `softmax_calibration.model` — 勝率の校正モデル
- `categories.json` — カテゴリ変数の水準(予測時の整合性に必須)
- `experiment_*.json` — 実験ログ(再現用)

### ステップ4: 予測

**レースIDが必要です。** レースIDはnetkeibaのURLに含まれる12桁の数字です。

例: `https://race.netkeiba.com/race/shutuba.html?race_id=202506050811`
→ レースID = `202506050811`

```bash
python main.py predict --race-id 202506050811
```

出力される情報:
- 各馬の **モデル単独の勝率** (`model_prob`、校正済み、レース内合計1.0)
- 各馬の **勝率** (`win_prob`。ライブオッズが取れた場合はモデルと市場の結合モデルの勝率)
- 各馬の **期待値** (勝率 × オッズ × 安全マージン)
- 期待値が1.1を超える馬が **購入候補** として表示されます

結果は `data/prediction_レースID.csv` に保存されます。

#### 予算を指定して購入金額を出す

```bash
python main.py predict --race-id 202506050811 --budget 10000
```

予算を資金とみなして、単勝の購入金額(`stake` 列、100円単位で切り捨て)を出します。配分は **分数ケリー基準** です:

- 期待値(勝率 × オッズ × 安全マージン)が `min_expected_value` 以上の馬だけを候補とし、
  候補内で資金の対数成長率が最大になる比率(ケリー比率)を求め、`config.yaml` の `betting.kelly_fraction` 倍(既定 0.25)します
- 購入合計は予算以下です。全額を使い切るとは限りません(期待値の高い馬がいなければ購入なし)
- 「期待値の合計が最大」の配分(予算全額を期待値最大の1頭に賭ける)は、資金を繰り返し賭けると破産確率が非常に高いため採用していません
- 対象は単勝のみです(DBには単勝以外のオッズがないため)

### (任意) シミュレーション

学習済みモデルの性能を、過去データで検証します。
半年ごとにテスト期間をスライドさせる「ウォークフォワード検証」を行います。
`build-features` で生成済みの特徴量を読み込むため、先に `build-features` を実行してください。
最初のテスト期間の開始日は `config.yaml` の `simulation.test_start` で設定します。

```
python main.py simulate
```

各期間ごとに以下が表示されます:
- 購入件数 / 的中率 / 回収率 (単勝・複勝それぞれ)
- 勝率予測精度 (レース単位LogLoss・Brier): LambdaRank / 二値分類 / 結合(combined: モデル+市場) / 市場(market) / 市場のみ再校正(market_recal)
- 結合モデルのモデルの重み alpha とその標準誤差

最後に全期間通算の結果として、上記の精度、LogLoss差の95%信頼区間、回収率の95%信頼区間(いずれもレース単位ブートストラップ)が表示されます。

**見方:**
- モデルの LogLoss が market より小さくない限り、「市場より正確な確率推定」という根拠はありません
- 結合モデルの改善がモデルによるものかは「combined - market_recal」のLogLoss差で判断します。この差の信頼区間の上限が0未満で、alpha/SE がおおむね2以上のときだけ、モデルが市場に無い情報を持つと言えます
- combined が market を下回っても、market_recal との差が有意でなければ、改善は市場確率の偏りの補正にすぎません
- 回収率の信頼区間の下限が100%を超えていない限り、利益が出るとは判断できません(1期間の回収率100%超は偶然でも頻繁に起こります)

**資金推移シミュレーション:** 最後に、初期資金(`simulation.initial_bankroll`、既定10万円)から全テスト期間を通して
予測の購入ルール(分数ケリー)で単勝を買い続けた場合の最終資金・最大ドローダウン・回収率を lambdarank / binary / combined ごとに表示します。
日次の資金推移は `models/bankroll_<label>.csv` に保存されます。

- 発走時刻のデータがないため、同じ日のレースはすべてその日の開始時点の資金で同時に購入し、日の終わりに精算したとみなします(同日の購入合計が資金を超える場合は比例縮小)
- 購入判定には確定オッズを使っており、実際に購入できる時点のオッズより有利です。結果は楽観側に偏ります
- 自分の購入によるオッズの低下(パリミュチュエル方式)は考慮していません。資金が大きくなるほど結果は非現実的になります

## よくある質問

### Q. スクレイピングが途中で止まったら？

そのまま同じコマンドを再実行してください。取得済みのページは自動でスキップされます。

### Q. データを追加したい

新しい期間を `scrape` して、`build-features` → `train` を再実行するだけです。
古いデータを消す必要はありません。

### Q. 予測の精度を上げるには？

1. **データ量を増やす** — 最も効果が大きい。5年分以上を推奨
2. `python main.py train --tune` でハイパーパラメータ探索を行う
3. `config.yaml` の `betting.min_expected_value` を上げると購入基準が厳しくなる(的中率は下がるが回収率は上がりやすい)

### Q. 地方競馬にも使える？

現在はJRA(中央競馬)のみ対応です。`get_race_ids_by_date` はnetkeibaの全レースを返すため、地方競馬のIDも混入する可能性があります。JRAのレースIDは先頭4桁の場コードが01〜10です。

### Q. 本当に儲かる？

**保証はできません。** 競馬の控除率は約25%(単勝)であり、ランダムに購入した場合の期待回収率は約75%です。このシステムは期待値ベースの判断により回収率の向上を目指しますが、利益を保証するものではありません。投資は自己責任でお願いします。

## フォルダ構成

```
競馬/
├── main.py                  ← メインのCLI (ここからすべて実行)
├── config/
│   └── config.yaml          ← 設定ファイル (学習期間・パラメータ)
├── src/
│   ├── scraping/            ← データ取得 (netkeiba)
│   ├── preprocessing/       ← データ整形・特徴量生成
│   ├── training/            ← モデル学習・キャリブレーション
│   ├── predict/             ← 未来レース予測
│   ├── simulation/          ← 過去データでの検証
│   └── policies/            ← 購入判定ロジック
├── tests/                   ← テストコード
├── data/                    ← 取得データ・特徴量 (自動生成)
│   ├── html/                ← スクレイピングしたHTML (gzip)
│   ├── db.sqlite            ← パース済みデータ
│   └── features/            ← 特徴量Parquet
└── models/                  ← 学習済みモデル (自動生成)
```

### 初回セットアップ (一度だけ)

```bash
# 1. 環境構築
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 2. 過去データの大量取得 (数日かかる。途中で止めても再開可能)

#    target_years_train: [2018, 2019, 2020, 2021, 2022, 2023]
```
